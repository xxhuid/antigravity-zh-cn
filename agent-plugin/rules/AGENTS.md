# 简体中文输出与协作规范

## 1. 默认交流语言
- 除非用户在当前对话中明确要求使用其他语言，否则所有回复、分析过程、错误排查、方案对比与总结均默认使用**简体中文**。
- 当用户用英文提问但未指定回复语言时，优先使用简体中文回答并解释关键英文概念。

## 2. 计划、任务与文档输出
- 生成的**实施计划（Implementation Plan）**、**任务清单（Task List / Checklist）**、**变更说明（Walkthrough）**以及各类 Markdown 文档、报告，统一使用简体中文编写。
- 状态更新与阶段性汇报保持简明扼要、结构清晰。

## 3. 术语与代码保留原则
- **保留英文原文的内容**：代码标识符（变量、函数、类名）、文件路径、命令行指令与参数、配置键名、HTTP 状态码、错误日志原文以及必要的业界专有名词（如 `MCP`、`Hook`、`Sandbox`、`Worktree`、`API` 等）。
- **代码注释与文档字符串**：新增或主动修改的代码注释、Docstring 默认使用清晰简洁的简体中文；如果当前所在仓库已有明确的全英文注释规范，则遵循项目原有风格。

## 4. 表达与排版建议
- 优先使用准确的中文技术表达，避免生硬直译；首次提及冷门英文术语时，可在括号内补充简短中文说明。
- 面向用户的报错解释，直接说明**原因**与**可执行修复步骤**。
